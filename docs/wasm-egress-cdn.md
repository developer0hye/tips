# 브라우저에서 다 처리해도 서버 비용은 0이 아니다 — WASM과 egress

"파일을 서버에 올리지 않고 브라우저에서 WASM으로 처리한다. 서버는 정적 파일만 내려주면 되니 비용이 들 게 없다."

절반만 맞다. **연산 비용은 진짜로 0이 된다.** 그런데 그 연산을 수행할 코드 자체를 방문자마다 내려보내야 한다. 그리고 그 코드가 45 MB라면, 없앤 줄 알았던 비용이 다른 항목으로 돌아온다.

## egress가 뭔가

**egress는 서버에서 인터넷으로 나가는 데이터다.** 반대는 ingress, 들어오는 데이터다.

핵심은 **AWS가 나가는 것만 과금하고 들어오는 건 무료**라는 점이다.

| 방향 | 예시 | 요금 |
|---|---|---|
| ingress (들어옴) | 사용자가 파일을 업로드 | **무료** |
| egress (나감) | 사용자가 WASM/이미지/JS를 다운로드 | **과금** |

서울 리전(`ap-northeast-2`) 기준으로 계정 전체에 매달 100 GB까지 무료, 그 이후 GB당 $0.126이다.

여기서 직관과 어긋나는 결론이 하나 나온다. **파일을 업로드받는 서비스가 대역폭 요금은 오히려 싸다.** 업로드는 ingress라 공짜다. "업로드 없이 브라우저에서 처리"하는 쪽이 비싸질 수 있는 이유는, 업로드를 없앤 대신 **처리 엔진을 매번 내려보내기 때문**이다.

## 실측: WASM은 생각보다 훨씬 크다

Rust로 짠 오피스 문서 → PDF 변환기([office2pdf](https://github.com/developer0hye/office2pdf))를 `wasm32-unknown-unknown`으로 빌드해서 재봤다.

```sh
wasm-pack build crates/office2pdf --release --target web --features wasm
```

| | 크기 |
|---|---|
| raw | **44,979,149 B (42.9 MiB)** |
| gzip -9 | 19,006,168 B (18.1 MiB) |
| brotli -11 | **12,315,409 B (11.7 MiB)** |

`wasm-opt`이 이미 적용된 뒤의 수치고, 중국어 폰트 기능은 **빼고** 잰 것이다(넣으면 +3.5 MB).

왜 이렇게 큰가. 이 라이브러리는 [Typst](https://github.com/typst/typst) 조판 엔진을 통째로 품고 있고, 거기에 폴백 폰트까지 임베드한다. 같은 코드의 네이티브 바이너리도 압축 상태로 27~30 MB다. **"라이브러리 하나 붙이는 것"이 45 MB짜리 다운로드가 되는 구간이 실제로 존재한다.**

교훈은 단순하다. **배포를 결정하기 전에 압축 후 크기를 직접 재라.** 나는 30 MB쯤이겠거니 어림했는데 실제로는 45 MB였다.

## 무료 티어를 나눠보면

```
100 GB ÷ 45 MB ≈ 2,200회
```

**한 달 방문자 2,200명이면 계정 전체의 무료 egress가 끝난다.** 그 사이트 하나가 아니라 계정에 있는 모든 리소스가 공유하는 한도다.

압축도 안 하고 페이지 진입 시마다 받게 두면 이렇게 는다.

| 월 방문자 | egress | 월 요금 |
|---|---|---|
| 2,200 | 100 GB | $0 (한도 정확히 소진) |
| 10,000 | 450 GB | 약 $44 |
| 100,000 | 4.5 TB | 약 $554 |

전부 투사치다. 실제로 이 금액을 낸 게 아니라, **고치지 않으면 트래픽이 늘 때 이 기울기로 오른다**는 뜻이다. 반대로 방문자가 월 300명 수준이면 요금은 정말로 $0이다. 위험은 지금 나가는 돈이 아니라 **기울기**에 있다.

## 기본값 세 개가 전부 틀려 있다

운영 중인 사이트를 재보니 셋 다 나왔다. 하나씩 확인하는 법과 함께 적는다.

### 1. 페이지 진입 시 로드 (eager load)

```js
// 마운트되자마자 45 MB를 받기 시작한다
useEffect(() => {
  initWasm();
}, []);
```

들어왔다 그냥 나가는 사람도 전부 다운로드한다. **이탈률이 80%면 트래픽의 80%가 버려지는 것이다.** 사용자가 실제로 파일을 고른 시점에 받게 바꾸는 것만으로 대부분이 사라진다. 애플리케이션 코드만 고치면 되고, 효과는 이 목록에서 제일 크다.

### 2. 압축이 아예 안 걸림

nginx의 `gzip_types` 기본값은 `text/html` 하나뿐이다. `application/wasm`도 `application/javascript`도 압축되지 않는다.

```sh
curl -sI -H "Accept-Encoding: gzip, br" https://example.com/app.wasm \
  | grep -iE "content-encoding|content-length"
```

응답에 `Content-Encoding`이 없고 `Content-Length`가 원본 크기 그대로면 압축이 안 되고 있는 것이다. WASM은 Brotli로 보통 3~4배 줄어든다. 재본 사례에서는 45 MB → 11.7 MB, **3.6배**였다.

주의할 점이 하나 있다. Ubuntu 기본 nginx 패키지에는 `ngx_brotli` 모듈이 없다. gzip만 켜거나(2.4배), 빌드 시점에 미리 압축한 `.br` 파일을 만들어 두거나, CDN이 대신 압축하게 하는 세 가지 선택지가 있다.

### 3. `Cache-Control: max-age=0`

```
Cache-Control: public, max-age=0
```

`public`이라 캐시는 되지만 `max-age=0`이라 **방문할 때마다 조건부 요청을 보낸다.** 보통은 304로 끝나지만 왕복 한 번은 매번 생기고, 재배포로 ETag가 바뀌면 전원이 45 MB를 다시 받는다.

파일명에 내용 해시를 넣고 `immutable`을 붙이면 재방문자의 전송량이 0이 된다.

```
app.a3f9c1.wasm    Cache-Control: public, max-age=31536000, immutable
```

## CDN은 최적화가 아니라 전제조건이다

압축과 lazy load는 **기울기를 낮출 뿐이다.** 방문자가 늘면 요금도 여전히 따라 는다. CDN은 축 자체를 바꾼다.

```
[전]  방문자 100,000명 → EC2 한 대            → EC2가 100,000번 내보냄
[후]  방문자 100,000명 → CDN 엣지 (수백 곳)   → EC2는 엣지당 한 번만 내보냄
                              ↓ 캐시 미스일 때만
                            EC2
```

원본은 엣지를 채울 때만 파일을 내보내고, 나머지는 CDN이 자기 대역폭으로 처리한다. Cloudflare 무료 플랜은 **캐시된 트래픽이 무제한**이라 그 부분 요금이 $0이다. 결과적으로 **egress가 방문자 수에 비례하지 않게 된다.**

| 100,000 방문자 기준 | AWS egress | 요금 |
|---|---|---|
| 그대로 | 4.5 TB | 약 $554 |
| + lazy load + Brotli | 234 GB | 약 $17 |
| + CDN | 거의 0 | **$0** |

앞의 두 줄은 완화고, **평평하게 만드는 건 마지막 줄뿐이다.**

### 붙일 때 걸리는 것 세 가지

**캐시 규칙을 명시해라.** CDN마다 기본으로 캐시하는 확장자 목록이 다르고 `.wasm`이 거기 있는지는 확신할 수 없다. 경로에 대해 캐시 규칙을 직접 거는 편이 확실하다.

**원본이 `max-age=0`을 보내면 캐시가 안 된다.** 위의 3번을 고치지 않으면 CDN을 붙여도 계속 원본까지 되물어본다. 두 작업은 세트다.

**원본 IP가 노출되면 우회당한다.** DNS를 CDN으로 돌려도 과거 DNS 기록에 원본 IP가 남는다. 보안 그룹을 CDN 대역으로만 열어두지 않으면 IP를 아는 쪽은 CDN을 건너뛰고 원본을 직접 때릴 수 있다.

**순서가 중요하다.** CDN은 트래픽이 오기 전에 붙여야 한다. 나중에 붙이면 그 사이 기간의 요금은 그대로 낸다.

## 정리

- 브라우저 처리로 없어지는 건 **연산 비용이지 대역폭 비용이 아니다.** 오히려 엔진을 매번 내려보내느라 대역폭은 늘어날 수 있다.
- AWS는 **나가는 것만 과금한다.** 업로드는 공짜고 다운로드가 돈이다.
- **배포 전에 압축 후 크기를 직접 재라.** 어림한 값과 2배 가까이 차이 났다.
- `eager load` / 무압축 / `max-age=0` — **기본값 세 개가 전부 틀려 있다.** 셋 다 curl 한 줄로 확인된다.
- 압축과 lazy load는 기울기를 낮추고, **CDN만이 기울기를 없앤다.**
- 지금 요금이 $0이어도 안심할 근거는 아니다. 무료 티어 100 GB는 45 MB 파일 기준 **2,200명이면 끝난다.**

## 확인 명령 모음

```sh
# 압축 여부와 실제 전송 크기
curl -sI -H "Accept-Encoding: gzip, br" https://example.com/app.wasm \
  | grep -iE "content-encoding|content-length|cache-control"

# 압축하면 얼마나 줄어드는지 로컬에서 재보기
gzip -9 -c app.wasm | wc -c
brotli -q 11 -c app.wasm | wc -c

# CDN을 거치는지 (Cloudflare면 cf-cache-status가 붙는다)
curl -sI https://example.com/app.wasm | grep -iE "^(server|cf-cache-status|age|x-cache)"

# 도메인이 원본 IP를 그대로 노출하는지
dig +short example.com A
```
