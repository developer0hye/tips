# 관리자 API 인증 누락 방지 팁

"관리자 화면이 로그인 뒤에만 보이니까 안전하다"는 생각은 틀렸습니다. 화면을 숨겨도 API 경로를 직접 호출하면 데이터가 그대로 나올 수 있습니다. 아래는 이런 문제가 생기는 대표 패턴과 점검·예방 방법입니다.

## 1. 자주 생기는 원인

| 원인 | 설명 |
| --- | --- |
| 미들웨어 적용 범위 누락 | 인증 미들웨어를 일부 라우트에만 붙이고, 새로 추가한 관리자 라우트를 보호 그룹 밖에 등록 |
| 프론트엔드에서만 인증 | 메뉴만 숨기고 API는 토큰·세션을 검사하지 않음 |
| 앞단 게이트웨이 규칙 | 로드밸런서·리버스 프록시에서 특정 경로를 인증 없이 통과시킴. 앱 코드가 맞아도 우회됨 |
| 인가(권한) 누락 | 로그인은 확인하지만 관리자 역할인지는 확인하지 않음 |
| 숨긴 이름에 의존 | 공인 인증서를 발급받으면 인증서 투명성(CT) 로그에 호스트명이 공개됨 |

## 2. 잘못된 예와 올바른 예

잘못된 예 (라우터 일부에만 인증 적용):

```js
app.use("/api/user", requireAuth, userRouter);
app.use("/api/admin", adminRouter);   // 인증 없음
```

올바른 예 (관리자 라우터 전체에 인증과 역할 검사 적용):

```js
app.use("/api/admin", requireAuth, requireRole("admin"), adminRouter);
```

핵심은 보호 여부를 라우트마다 기억하지 않고, 경로 그룹 단위로 강제하는 것입니다.

## 3. 점검 방법

- 모든 관리자 경로를 **토큰 없이** 호출했을 때 401 또는 403이 나오는지 확인합니다.
- 일반 사용자 토큰으로 관리자 경로를 호출했을 때 403이 나오는지 확인합니다.
- 앞단 게이트웨이 규칙과 앱 라우터 등록 목록을 함께 비교해서 불일치가 없는지 확인합니다.
- 외부에 노출된 호스트 목록을 CT 로그와 DNS 존 파일로 정기 확인합니다.

## 4. 예방 원칙

- 기본 정책은 "전부 차단, 필요한 것만 허용"입니다. 새 라우트는 인증이 필요한 상태로 시작합니다.
- 인증과 권한 검사는 서버에서 강제합니다. 프론트엔드 검사는 편의 기능일 뿐입니다.
- 3번의 무인증 호출 검사를 자동화 테스트에 넣어서, 라우트가 추가될 때마다 실행되게 합니다.
- 보호가 필요한 경로 목록을 코드에 명시하고, 목록에 없는 관리자 경로가 생기면 CI에서 실패하도록 합니다.
