# 손 안 닿는 장비에 에이전트 프레임워크를 올리며 배운 네 가지 — SSH 다단, 도커 방화벽, 컨텍스트, 그리고 "뜬다 ≠ 된다"

노트북에서 직접 닿지 않는 장비에 LLM 에이전트 프레임워크를 올렸다. 경로는 네 단계였다.

```
노트북 → 공인망 bastion → 사내 Windows 데스크톱 → 그 뒤의 GPU 장비
```

백엔드는 GPU 장비 로컬에 띄운 **OpenAI 호환 LLM 엔드포인트**였고, 프레임워크는 도커 컴포즈로 도는 것이었다. "컨테이너 하나 올리는 일"이라고 생각했는데 네 군데서 막혔다. 전부 특정 장비·제품과 무관한, **구조에서 나오는** 문제였다. 그래서 적어둔다.

## 1. 중첩 ssh에서 가장 안쪽 ssh는 stdin을 기다리다 멈춘다

여러 단을 거치려면 `ssh`를 중첩하게 된다.

```bash
ssh bastion 'ssh windows "ssh target \"명령\""'
```

이렇게 하면 **가장 안쪽 ssh가 응답 없이 몇 분씩 멈춘다.** 에러도 안 난다. 원인은 stdin이다. 중간 단계가 넘겨준 입력 스트림을 안쪽 ssh가 "앞으로 올 명령"으로 알고 끝없이 기다린다.

> 터미널을 붙이지 않는 비대화형 ssh에는 `-n`을 준다. `-n`은 stdin을 `/dev/null`로 돌려 "입력 없음"을 분명히 한다.

```bash
ssh bastion 'ssh windows "ssh -n target \"명령\""'   # 안 멈춘다
```

반대로 **스크립트나 파일을 stdin으로 일부러 흘려보낼 때는 `-n`을 빼야 한다.** 둘을 헷갈리면 한쪽은 멈추고 다른 쪽은 빈 입력을 받는다.

이어서 같은 다단 환경에서 유용했던 것들:

- **여러 줄 원격 스크립트는 인자 말고 stdin으로.** 따옴표 지옥을 피한다.
  ```bash
  ssh target bash -s <<'EOF'
  여러 줄
  스크립트
  EOF
  ```
- **파일 전송은 scp 대신 파이프 + 양방향 sha256 검증.** 중간에 Windows 단이 끼면 scp 경로가 꼬이기 쉽다.
  ```bash
  ssh ... "cat > /원격/경로" < 로컬파일      # 보내기
  ssh ... "cat /원격/경로" > 로컬파일        # 받기
  # 양쪽에서 sha256을 떠서 같은지 확인한다
  ```
- **설정 파일은 base64로 싸서 보낸다.** 여러 셸을 통과하며 따옴표·개행이 깨지는 걸 원천 차단한다. 받는 쪽에서 `base64 -d`.
- **Windows 단에서 PowerShell은 `-EncodedCommand`로.** 명령을 UTF-16LE로 바꿔 base64로 넘기면 따옴표·코드페이지 깨짐을 피한다. 한글이 `???`로 나오던 게 사라진다. 출력에 섞여 나오는 CLIXML 진행률 노이즈는 `-NonInteractive`와 `$ProgressPreference="SilentlyContinue"`로, 그래도 남으면 `grep -v`로 걸러낸다.

## 2. 도커 브리지 컨테이너는 '남의 호스트'엔 닿아도 '자기 호스트'엔 못 닿을 수 있다

프레임워크 컨테이너를 GPU 장비에 올리고, 같은 장비의 로컬 LLM(`127.0.0.1:PORT`)에 물렸다. 그런데 컨테이너에서 그 LLM으로 가는 호출이 전부 **연결 실패(000)**였다. 설정은 맞는데 호출만 안 됐다.

버리는 컨테이너 하나로 경로를 찍어보면 금방 드러난다.

```bash
docker run --rm --entrypoint sh <이미지> -lc '
  for t in 자기호스트:PORT 게이트웨이:PORT 다른호스트:PORT; do
    echo -n "$t -> "; curl -s -m4 -o /dev/null -w "%{http_code}\n" http://$t/...
  done'
```

결과가 이렇게 갈렸다.

| 대상 | 결과 |
|---|---|
| 자기 호스트의 서비스 | **000 (실패)** |
| 도커 브리지 게이트웨이 | **000 (실패)** |
| **같은 LAN의 다른 호스트** | **200 (성공)** |

즉 브리지 컨테이너는 **LAN의 다른 장비에는 닿는데(FORWARD 체인 허용), 자기 호스트로 돌아오는 트래픽만 막혀 있었다**(호스트 INPUT 체인이 도커 브리지 대역을 드롭). 호스트 자체 방화벽이 몇 개 포트만 열어둔 환경이면 흔하다.

빠져나갈 길을 따져보면:

- **호스트 네트워크(`network_mode: host`)**로 바꾸면 `127.0.0.1`엔 닿는다. 하지만 이번엔 **앱의 포트가 호스트 방화벽의 적용을 받아** 바깥에서 접속이 막혔다. 방화벽을 열려면 root가 필요한데 없었다.
- 결국 **그 컨테이너를 다른 장비에서 돌렸다.** LAN 너머 엔드포인트로는 잘 닿으니(위 표의 200), LLM에 LAN으로 접근할 수 있는 별도 장비에 프레임워크를 올리는 쪽이 깔끔했다.

> "컨테이너를 어느 장비에 둘까"는 취향이 아니라 **네트워크 도달성 문제**다. 서비스가 있는 장비가 꼭 프레임워크를 올릴 장비는 아니다.

## 3. 에이전트는 컨텍스트를 크게 먹는다 — 기본 출력 상한이 창을 넘긴다

연결을 고치자 이번엔 프레임워크가 첫 LLM 호출부터 **HTTP 400**으로 죽었다.

```
request (12356 tokens) exceeds the available context size (8192 tokens)
```

```
you requested 32768 output tokens and your prompt contains ~10k tokens
```

원인이 둘이었고 뿌리는 같았다 — **"프롬프트 + 요청한 출력 토큰"이 모델 컨텍스트 창을 넘겼다.**

- **프레임워크 쪽**: 출력 토큰 상한의 기본값이 과하게 컸다(예: 32768). 에이전트 프롬프트가 수 k~십수 k인데 거기에 32768 출력까지 요청하면 32768짜리 창은 그냥 넘는다. **모델의 컨텍스트 창 크기를 프레임워크에 알려주고, 출력 상한을 현실적인 값으로 낮춘다.**
- **추론 서버 쪽**: 멀티슬롯 서버는 전체 컨텍스트를 슬롯들이 **나눠** 쓴다. llama.cpp의 `-np N -c C`면 **슬롯당 컨텍스트 = C / N**이다. 슬롯 16개에 `-c 131072`를 주면 슬롯 하나는 8192뿐이라, 프롬프트 하나가 그걸 넘겨 바로 400이 났다. 동시성을 욕심내 슬롯을 늘리면 **슬롯마다 굶는다.**

> 에이전트 워크로드는 긴 컨텍스트가 전제다. 일반 챗 감각으로 슬롯을 많이 깔면, 슬롯당 창이 프롬프트 하나도 못 담는다. **슬롯 수는 "프롬프트 하나가 통째로 들어갈 만큼"을 기준으로 적게 잡는다.**

## 4. "포트가 뜬다"와 "일이 된다"는 다르다

위의 400은 **헬스체크로는 안 잡혔다.** `/health`는 200, 로그인도 200, 컨테이너→LLM 경로도 200이었다. 전부 초록불인데 정작 **실제 작업의 첫 모델 호출에서** 터졌다.

> 초기 설정의 400은 보통 헬스 엔드포인트가 아니라 **첫 진짜 작업**에서 나온다. "포트가 떴다", "로그인이 된다"는 **도달성**이지 **동작**이 아니다.

에이전트 서비스는 **실제 모델 왕복 한 번, 또는 실제 작업 스텝 하나**까지 돌려보고 "된다"고 말해야 한다. 거기까지 안 가보면, 사용자가 첫 작업을 돌리는 순간 똑같은 400을 처음 보게 된다.

## 실천 방법

1. **중첩 ssh의 안쪽 비대화형 ssh엔 `-n`.** stdin으로 스크립트/파일을 흘릴 때만 뺀다. 여러 줄은 `bash -s <<'EOF'`, 파일은 파이프 + sha256, 설정은 base64로 싸서 보낸다.
2. **Windows 단은 PowerShell `-EncodedCommand`(UTF-16LE+base64).** 따옴표·한글 깨짐을 원천 차단하고 CLIXML 노이즈는 걸러낸다.
3. **컨테이너 배치는 네트워크 도달성으로 결정한다.** 자기 호스트에 못 닿고 LAN 너머엔 닿는 경우가 있다. 버리는 컨테이너로 자기호스트 vs 다른호스트 도달성을 먼저 찍어본다.
4. **에이전트용 LLM은 컨텍스트를 크게.** 프레임워크엔 모델 컨텍스트 창을 알려주고 출력 상한을 낮춘다. 멀티슬롯 서버는 **슬롯당 = 전체 / 슬롯수**를 계산해, 프롬프트 하나가 들어갈 만큼 슬롯을 적게 잡는다.
5. **"됐다"는 실제 작업 스텝으로 확인한다.** 헬스체크 200 말고, 모델 왕복 한 번 또는 작업 한 스텝을 끝까지 돌려본다.

## 한 줄 요약

> 다단 ssh는 stdin(`-n`)에서, 도커는 "자기 호스트 도달성"에서, 에이전트 LLM은 "프롬프트+출력 vs 컨텍스트 창"에서 막힌다. 그리고 포트가 떴다고 되는 게 아니다 — 첫 진짜 작업까지 돌려봐야 안다.
