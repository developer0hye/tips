# 사이버보안 특화 AI 모델을 위한 학습 용어 및 커리큘럼

> 작성 기준일: 2026-09-01  
> 권장 학습량: 주 8~10시간, 12주  
> 목표: 보안데이터를 이해하고, 이를 RAG·학습·AI 에이전트·평가에 올바르게 연결할 수 있는 수준

## 1. 먼저 이해해야 할 전체 그림

핵심은 “보안데이터를 많이 모아 LLM에 학습시키면 된다”가 아니라는 점이다. 다음 네 가지를 구분하는 것이 출발점이다.

1. **최신 지식과 근거가 필요한 문제**는 RAG·지식그래프로 해결한다.
2. **반복되는 판단·분류·출력 형식**은 SFT와 Post-training으로 안정화한다.
3. **실시간 조회·분석·조치**는 AI 에이전트와 보안도구 연계로 수행한다.
4. **효과와 안전성 검증**은 학습과 분리된 비공개 평가셋으로 수행한다.

| 보안 영역 | 대표 데이터 | LLM·AI 활용 방식 | 핵심 검증 질문 |
|---|---|---|---|
| 보안지식·CTI | 표준, 가이드, 위협그룹, TTP, IoC | RAG, 지식그래프, 근거형 응답 | 최신 정보와 근거를 정확히 사용했는가? |
| 취약점·소스코드 | 취약/정상 코드, CVE·CWE, 패치, 테스트 | 코드 SFT, 검증기, Tool-use | 취약 원인과 패치를 실행으로 검증했는가? |
| 악성코드 | 정·동적 분석, API 시퀀스, 샌드박스 행위 | 전용모델, SFT, 분류·요약 | 패밀리·행위·TTP를 혼동하지 않는가? |
| 네트워크·엔드포인트·클라우드 | Flow, PCAP, 프로세스, 파일, IAM, Audit Log | 시퀀스·그래프 분석, 에이전트 관측 | 여러 증적을 시간·자산·세션으로 연결하는가? |
| SOC·침해사고·포렌식 | Alert, Case, 쿼리, 증적, Timeline, 조치 결과 | SFT, Post-training, RAG, Tool-use | 조사에서 조치·복구까지 완결하는가? |
| Cyber Range·AI 보안 | 환경 상태, 권한, 행동-관측, 공격·방어 결과 | 에이전트 학습, 샌드박스 평가 | 권한을 넘지 않고 실패를 복구하는가? |
| 평가·국내 환경 | 비공개 Test, 한국어, 국내 SW·클라우드 환경 | 독립 평가, 회귀시험 | 공개 벤치마크가 아닌 실제 환경에서도 동작하는가? |

## 2. 보안 트랙: 공부해야 할 용어와 기술

### 2.1 보안 기본 개념과 거버넌스

| 용어·기술 | 핵심 의미 | 왜 중요한가 | 최소 실습 |
|---|---|---|---|
| 기밀성·무결성·가용성(CIA) | 보호해야 할 정보보안의 기본 속성 | 공격 영향과 정책 목표를 정의하는 출발점 | 사고 사례 하나를 CIA 영향으로 분류 |
| 자산·위협·취약점·위험 | 보호대상, 공격 가능성, 약점, 예상 손실을 구분 | CVSS 점수만으로 실제 위험을 판단하는 오류 방지 | 자산 중요도와 위협정보를 반영한 위험표 작성 |
| 보안통제(Control) | 위험을 예방·탐지·대응하기 위한 관리·기술·물리 조치 | AI의 판단과 실제 통제 집행을 분리하기 위해 필요 | 통제 하나를 예방·탐지·대응으로 분류 |
| NIST CSF 2.0 | Govern, Identify, Protect, Detect, Respond, Recover의 위험관리 체계 | 보안데이터와 AI 과업을 전 주기에 배치하는 공통 틀 | 현재 데이터군을 6개 Function에 매핑 |
| 최소권한 | 사용자·서비스·AI 에이전트에 필요한 권한만 부여 | Tool-use의 권한 초과와 피해 범위를 제한 | 읽기 도구와 쓰기 도구 권한을 분리 설계 |
| RBAC·ABAC | 역할 기반·속성 기반 접근통제 | 데이터셋·RAG 문서·보안도구의 세밀한 접근통제에 필요 | 사용자·프로젝트·민감도 기반 정책 예시 작성 |
| 감사로그 | 누가 언제 무엇을 열람·변경·실행했는지 기록 | 데이터 반출, RAG 조회, 에이전트 행동을 추적 | 호출-입력-출력-결과를 남기는 로그 스키마 설계 |

**도달 기준**

- 위협, 취약점, 위험, 통제를 서로 바꾸어 쓰지 않는다.
- AI 모델의 정확도와 조직의 보안위험 감소를 별도 지표로 설명할 수 있다.
- 사람 승인, 최소권한, 감사로그가 필요한 고위험 조치를 식별할 수 있다.

### 2.2 CTI와 공격행위 모델링

| 용어·기술 | 핵심 의미 | 꼭 구분할 것 | 최소 실습 |
|---|---|---|---|
| CTI(Cyber Threat Intelligence) | 공격자·캠페인·인프라·기법·피해대상의 맥락을 갖춘 위협정보 | 단순 IoC 목록과 맥락 있는 인텔리전스 | 공개 보고서에서 엔터티와 관계 추출 |
| IoC | IP, 도메인, URL, 해시처럼 침해를 나타낼 수 있는 관측값 | 유효기간·신뢰도·오탐·폐기 상태 | IoC에 first_seen, last_seen, confidence 추가 |
| IoA | 공격자가 수행하는 행위·패턴 중심 지표 | 정적 값인 IoC보다 행위 일반화에 유리 | 이벤트를 자격증명 접근·지속성 등으로 분류 |
| TTP | 공격자의 전술·기술·절차 | Tactic은 목적, Technique은 방법 | 사고 하나를 ATT&CK Technique에 매핑 |
| MITRE ATT&CK | 공격행위를 Tactic·Technique·Sub-technique으로 구조화한 지식베이스 | 공격단계와 탐지 커버리지 분석에 사용 | ATT&CK Navigator 형태의 탐지 커버리지표 작성 |
| STIX 2.1 | CTI 객체와 관계를 JSON으로 표현하는 표준 | Indicator, Malware, Campaign, Relationship 구분 | 5개 객체와 관계를 가진 STIX Bundle 작성 |
| TAXII 2.1 | CTI를 교환·조회하기 위한 전송 API 규격 | STIX는 데이터 모델, TAXII는 전달 방식 | Collection/API 기반 증분 수집 흐름 설계 |
| 신뢰도·관측시점·폐기상태 | CTI의 품질과 최신성을 판단하는 메타데이터 | 오래된 IoC를 현재 사실처럼 쓰지 않기 | 동일 IoC의 상태변경 이력 모델링 |

**도달 기준**

- IoC, IoA, TTP의 차이를 사례로 설명할 수 있다.
- CTI를 문서 덩어리가 아니라 엔터티·관계·시간정보로 표현할 수 있다.
- LLM이 폐기된 IoC를 사용하지 않도록 RAG 필터 조건을 설계할 수 있다.

### 2.3 취약점·소스코드 보안

| 용어·기술 | 핵심 의미 | 역할 | 최소 실습 |
|---|---|---|---|
| CVE | 공개적으로 식별된 취약점의 식별자 | 취약점, 패치, 공격관측을 연결하는 키 | CVE 하나의 설명·영향제품·패치 연결 |
| CWE | 코드·설계상의 약점 유형 분류 | LLM의 취약 원인 분류 라벨 | 취약 코드 5개를 CWE로 분류 |
| CVSS v4.0 | 취약점의 기술적 심각도를 표현하는 점수·벡터 | Base 점수와 현장 위험을 구분 | Base·Threat·Environmental 차이 비교 |
| SAST | 소스·바이너리를 실행하지 않고 분석 | 코드 취약점 후보와 위치 제공 | 오픈소스 프로젝트에 정적분석 실행 |
| DAST | 실행 중인 애플리케이션을 외부에서 테스트 | 실제 동작 기반 취약점 검증 | 안전한 실습 앱에 동적 스캔 수행 |
| SCA | 오픈소스 구성요소·라이선스·취약점 분석 | 공급망·의존성 취약점 데이터 확보 | 의존성 목록과 알려진 취약점 연결 |
| SBOM | 소프트웨어 구성요소 명세 | 취약점과 실제 사용 자산의 연결 | 소규모 프로젝트의 SBOM 생성·검토 |
| Patch Diff | 취약 버전과 수정 버전의 코드 차이 | 원인·수정·회귀시험을 연결하는 핵심 학습쌍 | 패치 전후 변경과 보안 의미 설명 |
| PoC·Exploit | 취약점 재현 코드와 실제 공격 가능 구현 | 격리·접근등급·악용 방지 필요 | 코드는 실행하지 않고 전제조건·영향만 분석 |
| 회귀시험 | 패치가 기능을 깨뜨리지 않는지 확인 | “그럴듯한 패치”와 “검증된 패치”를 구분 | 보안 테스트와 기능 테스트를 함께 작성 |

**도달 기준**

- CVE, CWE, CVSS가 각각 식별자·분류·점수라는 것을 구분한다.
- LLM의 패치 설명을 그대로 신뢰하지 않고 빌드·테스트로 검증한다.
- 취약 코드, 정상 코드, 패치 실패 사례를 함께 데이터로 구성할 수 있다.

### 2.4 악성코드 분석

| 용어·기술 | 핵심 의미 | 학습 포인트 | 최소 실습 |
|---|---|---|---|
| 정적분석 | 실행하지 않고 파일 구조·문자열·코드·메타데이터 분석 | 안전하지만 난독화에 취약 | 안전한 샘플의 헤더·문자열·import 분석 |
| 동적분석 | 격리 환경에서 실행행위를 관찰 | 프로세스·파일·레지스트리·네트워크 행위 파악 | 공개 분석보고서의 행동 Timeline 재구성 |
| 샌드박스 | 악성 행위를 격리·관찰하는 실행환경 | 네트워크 egress와 스냅샷·복구가 중요 | 실행정책·격리·반출규칙 설계 |
| 해시 | 파일 식별과 무결성 확인에 쓰는 요약값 | 변형에 취약하므로 행위정보와 함께 사용 | SHA-256과 패밀리·행위 라벨 연결 |
| 패밀리·캠페인 | 유사 악성코드 계열과 공격활동 묶음 | 명칭 충돌과 다중 라벨에 주의 | 여러 벤더 명칭을 정규화한 매핑표 작성 |
| API·시스템콜 시퀀스 | 악성코드가 수행한 저수준 행위 흐름 | 시퀀스 학습·TTP 추론에 유용 | API 흐름을 ATT&CK 기법으로 변환 |
| 패킹·난독화 | 분석을 방해하도록 코드·데이터를 변형 | 정적 특징 편향과 일반화 실패 원인 | 원본·패킹본 특징 차이 비교 |
| YARA | 파일·메모리 패턴 기반 탐지 규칙 | 규칙 기반 검증기와 데이터 라벨링에 유용 | 안전한 문자열을 이용한 탐지 규칙 작성 |

**안전 원칙**

- 악성코드 원본은 일반 개발환경이나 개인 PC에서 실행하지 않는다.
- 실행 실습보다 공개 분석결과와 안전한 파생표현을 먼저 사용한다.
- 샌드박스, egress 통제, 스냅샷 복구, 반출심사를 갖춘 환경에서만 다룬다.

### 2.5 네트워크·엔드포인트·클라우드 관측

| 용어·기술 | 핵심 의미 | 연결해야 할 메타데이터 | 최소 실습 |
|---|---|---|---|
| PCAP | 패킷 원문 캡처 | 시간, 인터페이스, 수집지점, 자산 | PCAP에서 DNS·HTTP·TLS 흐름 추출 |
| Flow | 연결 단위의 요약 네트워크 기록 | 출발·목적 IP/Port, 바이트, 시간 | 세션별 정상·이상 통계 생성 |
| DNS·HTTP·TLS 메타데이터 | 이름해석·웹·암호화 통신의 관측정보 | 도메인, URI, 인증서, SNI, 상태코드 | 의심 도메인과 세션·자산 연결 |
| EDR | 엔드포인트 프로세스·파일·레지스트리·행위 관측·대응 | 사용자, 자산, 프로세스 트리, 해시 | Process Tree에서 원인 프로세스 찾기 |
| NDR | 네트워크 트래픽 기반 탐지·대응 | Flow, 프로토콜, 자산, 탐지규칙 | 동일 사건의 EDR·NDR 증적 결합 |
| SIEM | 다양한 로그를 수집·검색·상관분석하는 플랫폼 | 공통 시간·자산·사용자·세션 ID | 3개 로그 소스를 공통 스키마로 정규화 |
| Cloud Audit Log | 클라우드 API·관리행위 기록 | 계정, 역할, 리소스, 리전, 요청·결과 | 권한변경 Timeline 작성 |
| IAM | 사용자·서비스·역할·정책 기반 접근관리 | 주체, 역할, 권한, 리소스, 조건 | 과도한 권한과 실제 사용권한 비교 |
| 정상 기준선(Baseline) | 정상 환경에서 기대되는 행위 분포 | 조직·시간대·자산군·업무 특성 | 정상/위험 비율을 유지한 평가셋 작성 |
| 이벤트 상관분석 | 여러 센서의 이벤트를 하나의 사건으로 연결 | 시간동기화, 자산·사용자·세션·사건 ID | 로그인→실행→통신→파일변경 그래프 작성 |

**도달 기준**

- 개별 로그 행이 아니라 세션·사건·공격경로 단위로 생각한다.
- 정상 데이터가 없는 탐지 데이터셋의 오탐 문제를 설명할 수 있다.
- 네트워크, 엔드포인트, 클라우드 증적을 공통 시간축으로 결합할 수 있다.

### 2.6 SOC Workflow와 침해사고 대응

| 용어·기술 | 핵심 의미 | AI 적용 시 주의점 | 최소 실습 |
|---|---|---|---|
| Alert | 탐지규칙·모델이 생성한 의심 신호 | Alert는 사고 확정이 아님 | Alert를 정탐·오탐·추가조사로 분류 |
| Case·Ticket | 조사·판단·조치의 업무 단위 | 근거·담당자·상태변경 이력 필요 | 경보부터 종료까지 Case 스키마 작성 |
| Triage | 중요도와 우선순위를 빠르게 판단 | 심각도와 자산 중요도를 함께 고려 | 10개 경보 우선순위와 근거 작성 |
| 조사 가설 | 증적을 통해 검증할 잠정 설명 | 결론보다 가설-검증 과정이 중요 | 가설, 필요 증적, 반증조건 작성 |
| Playbook | 반복 대응절차를 단계화한 문서·자동화 흐름 | 조건분기·실패·승인·롤백 필요 | 피싱 또는 계정탈취 Playbook 작성 |
| SOAR | 보안도구·티켓·조치를 자동 연계 | 고위험 자동조치의 사람 승인 필요 | 읽기 전용 자동화와 쓰기 자동화 분리 |
| Escalation | 더 높은 전문성·권한이 필요한 단계로 이관 | 종료·승인조건을 명시 | 분석가 L1→L2→IR 이관기준 작성 |
| Containment | 피해 확산을 막는 격리·차단 | 업무영향과 롤백 계획 필요 | 호스트 격리 전 승인조건 정의 |
| Eradication·Recovery | 원인 제거와 서비스 정상화 | 탐지 성공과 복구 성공을 구분 | 복구 후 재발확인 체크리스트 작성 |
| Root Cause | 사고가 가능했던 근본 원인 | 최초 Alert와 Root Cause를 혼동하지 않기 | 5 Whys로 사고 원인 분석 |
| Timeline | 사건 전후 증적을 시간순으로 정렬 | 시간대·시계오차·수집지연 보정 | 3개 로그의 통합 Timeline 작성 |
| MTTD·MTTR | 탐지·대응까지 걸린 시간 지표 | 정확도 외 현업효과 측정 | 자동화 전후 처리시간 비교 |

## 3. LLM·AI 트랙: 공부해야 할 용어와 기술

### 3.1 LLM 기본 구조

| 용어·기술 | 핵심 의미 | 반드시 이해할 점 | 최소 실습 |
|---|---|---|---|
| Token·Tokenizer | 텍스트를 모델이 처리하는 단위와 변환기 | 보안 로그·코드·한글의 토큰 효율이 다름 | 한글, 코드, 로그의 토큰 수 비교 |
| Embedding | 텍스트·코드·개체를 의미 벡터로 표현 | 유사도는 사실성·권한·최신성을 보장하지 않음 | CTI 문장 20개의 유사도 검색 |
| Transformer·Attention | 문맥 내 요소 간 관계를 계산하는 모델 구조 | 장기 로그·대규모 코드에서는 문맥 한계 존재 | 짧은/긴 사건 Timeline 질의 비교 |
| Context Window | 한 번에 모델이 참조할 수 있는 입력 범위 | 길다고 중요한 정보가 항상 보존되지는 않음 | 증적 순서와 위치를 바꾼 성능 비교 |
| Base Model | 일반 데이터로 사전학습된 기반모델 | 보안 전문성과 최신성은 별도 보완 필요 | 동일 보안질문을 모델·프롬프트별 비교 |
| Inference | 학습된 모델로 결과를 생성하는 과정 | 지연, 비용, 재현성, 온도 설정을 함께 관리 | 온도별 일관성과 오류율 비교 |
| Hallucination | 근거 없이 사실처럼 잘못 생성하는 현상 | 보안에서는 잘못된 IoC·조치가 직접 위험 | 근거 없는 답변을 검출하는 평가셋 작성 |

### 3.2 학습과 적응

| 용어·기술 | 핵심 의미 | 적합한 보안데이터 | 주요 위험 |
|---|---|---|---|
| Pre-training | 대규모 데이터로 일반 언어·코드 능력을 학습 | 매우 큰 정제 문서·코드 코퍼스 | 비용, 데이터 권리, 평가 오염 |
| CPT·Continued Pre-training | 기존 모델에 추가 사전학습 수행 | 보안 언어·코드 분포가 일반 데이터와 크게 다를 때 | 일반능력 저하·망각 |
| DAPT | 특정 도메인 코퍼스로 적응 학습 | 보안문서, 분석보고서, 코드 | 최신 지식 고착, 중복·오염 |
| SFT | 입력과 모범 출력 쌍으로 지도 미세조정 | 취약점 분석, 트리아지, 사고보고, 도구선택 | 단일 스타일·라벨 오류 과적합 |
| Post-training | SFT 이후 선호·검증·안전성 등을 개선 | 비교판정, 정정, 실패·거부·검증결과 | 보상 해킹, 과정라벨 오류 |
| Preference Data | 두 답변 중 더 나은 답변과 이유 | 전문가 판정, 근거 충실도, 안전한 조치 | 취향과 사실 정확도 혼동 |
| Process Supervision | 중간 행동·검증단계에 피드백 제공 | 조사쿼리, 도구선택, 실행결과 | 숨은 추론 공개에 의존하지 말고 외부 행동·근거·검증결과를 사용 |
| Verifier | 출력의 규칙·실행·정답 여부를 검사 | 스키마, 빌드, 테스트, 정책, 권한 | 검증기의 빈틈을 이용하는 보상 해킹 |
| PEFT·LoRA | 일부 파라미터만 효율적으로 조정 | 소규모 과업 특화·실험 | 기반모델 변화와 adapter 호환성 |
| Catastrophic Forgetting | 특화 학습 후 일반능력이 저하되는 현상 | 보안데이터 비율·학습률·replay 관리 | 보안 성능만 보고 일반 회귀를 놓침 |
| Distillation | 강한 모델의 출력을 작은 모델로 이전 | 반복 트리아지·요약·분류 | 교사모델 오류·편향 복제 |
| Hard Negative | 헷갈리지만 정답은 음성인 어려운 사례 | 정상 관리자 행동, 유사 IoC, 안전한 코드 | 잘못된 음성 라벨이 결정경계를 훼손 |

**선택 기준**

- 지식이 자주 바뀌면 직접학습보다 RAG를 먼저 고려한다.
- 반복 출력 형식과 안정된 판단경계가 중요하면 SFT를 고려한다.
- 전문가 선호, 오류 수정, 안전한 거부가 중요하면 Post-training을 고려한다.
- 낮은 지연과 오프라인 동작이 필요할 때만 파라미터 내재화의 이점이 커진다.

### 3.3 RAG와 구조화 지식베이스

| 용어·기술 | 핵심 의미 | 보안 적용 체크포인트 |
|---|---|---|
| Chunking | 문서를 검색 가능한 단위로 분할 | 표·코드·문단·출처 경계를 훼손하지 않기 |
| Vector Search | 임베딩 유사도로 관련 문서 검색 | 유사하지만 오래되거나 폐기된 정보 필터링 |
| Keyword·Sparse Search | 용어·식별자 일치 중심 검색 | CVE, 해시, IP, ATT&CK ID 검색에 강점 |
| Hybrid Search | 벡터와 키워드 검색 결합 | 자연어 질문과 정확한 보안 식별자를 함께 처리 |
| Reranker | 검색 후보의 관련성을 다시 정렬 | 원 질문·문서·시점·권한을 함께 고려 |
| Knowledge Graph | 엔터티와 관계를 그래프로 저장 | 공격자-캠페인-TTP-IoC-자산 연결에 유용 |
| Grounding | 답변을 제공된 근거에 묶는 것 | 근거에 없는 단정 금지, 출처·시점 표시 |
| ACL-aware Retrieval | 사용자가 볼 수 있는 문서만 검색 | 검색 전 필터와 생성 후 검사를 모두 적용 |
| Freshness·Versioning | 최신·정정·폐기 상태 관리 | IoC·정책·취약점 상태 변경 시 재색인 |
| Retrieval Evaluation | 검색 단계 자체의 품질평가 | Recall@k, MRR, 근거 포함률, ACL 누출률 측정 |

**최소 구현 과제**

1. 보안 가이드와 CTI 보고서를 문서·청크·메타데이터로 저장한다.
2. 출처, 발행일, 관측시점, 신뢰도, 폐기상태, ACL 필드를 추가한다.
3. CVE·ATT&CK ID는 키워드 검색, 자연어는 벡터 검색으로 결합한다.
4. 답변에 근거와 유효시점을 표시한다.
5. 검색 실패, 폐기정보 사용, ACL 누출을 별도 평가한다.

### 3.4 AI 에이전트와 Tool-use

| 용어·기술 | 핵심 의미 | 보안 통제 |
|---|---|---|
| Tool Schema | 도구 이름·입력·출력·오류를 정의한 명세 | 허용 파라미터와 위험도를 명시 |
| Function Calling | 모델이 구조화된 도구 호출을 생성 | 스키마 검증과 서버측 권한검사 필수 |
| Action-Observation Trajectory | 행동과 관측의 연속 기록 | 성공뿐 아니라 실패·재시도·롤백 포함 |
| Planner·Executor | 계획 생성과 실제 실행 역할 분리 | 계획은 쓰기권한 없이 검토 가능하게 설계 |
| Sandbox | 실행 영향과 접근범위를 제한하는 격리환경 | 파일·네트워크·프로세스·자격증명 통제 |
| Human-in-the-loop | 고위험 행동에 사람 승인 삽입 | 차단·격리·삭제·계정변경 등에 적용 |
| Retry·Rollback | 실패 재시도와 원상복구 | 무한재시도·중복실행·부분실패 방지 |
| Idempotency | 같은 요청을 반복해도 결과가 중복되지 않는 성질 | 티켓·차단·격리 도구에서 중요 |
| Termination Condition | 업무가 끝났음을 판단하는 조건 | 목표달성·실패·위험·예산 초과 종료 구분 |
| Tool-use Evaluation | 도구 선택과 실행결과를 평가 | 성공률, 잘못된 호출, 권한위반, 복구율 측정 |

**AI 에이전트 설계 원칙**

- 조회와 변경 도구를 분리한다.
- 권한 판단은 LLM이 아니라 서버측 정책이 최종 결정한다.
- 고위험 조치는 사람 승인을 거친다.
- 입력·계획·호출·관측·결과·승인·롤백을 모두 기록한다.
- 도구 실패를 정상 학습·평가 사례에 포함한다.

### 3.5 합성데이터·데이터 품질

| 용어·기술 | 핵심 의미 | 확인할 것 |
|---|---|---|
| 합성데이터 | 규칙·시뮬레이터·생성모델로 만든 데이터 | 실제 분포와의 차이, 비실존성, 생성원 편향 |
| Data Augmentation | 기존 데이터의 표현·조건을 변형 | 의미·라벨 불변성이 유지되는가? |
| Weak Label | 규칙·모델·휴리스틱으로 만든 약한 정답 | 전문가 표본검수와 오류율 추정 |
| Data Lineage | 원천·정제·생성·라벨·split 이력 | 생성 프롬프트·시드·버전·체크섬 기록 |
| Deduplication | 동일·유사 데이터 중복 제거 | 문장뿐 아니라 사건·코드·캠페인 단위 중복 제거 |
| Distribution Shift | 학습과 실제 환경의 분포 차이 | 센서·조직·언어·공격기법·시간 변화 |
| Data Drift | 운영 중 데이터 분포가 변하는 현상 | 갱신·재라벨·재평가 조건 정의 |
| Label Agreement | 여러 검수자의 라벨 일치도 | 모호한 과업의 라벨 기준 개선 |

### 3.6 평가·벤치마크

| 용어·지표 | 핵심 의미 | 보안 AI에서의 사용 |
|---|---|---|
| Ground Truth | 검증된 정답 | 전문가 근거와 실행결과로 확인 |
| Train·Validation·Test Split | 학습·선택·최종평가 데이터 분리 | 행이 아닌 사건·캠페인·저장소·패밀리 단위 분리 |
| 비공개 Test Set | 모델·개발자가 미리 볼 수 없는 시험셋 | 벤치마크 과적합과 데이터 누수 방지 |
| Data Contamination | 시험정보가 학습·RAG·생성에 섞이는 문제 | 평가셋을 별도 저장소·권한으로 격리 |
| Precision | 탐지했다고 한 것 중 실제 정답 비율 | 과도한 경보·오탐 평가 |
| Recall | 실제 위험 중 탐지한 비율 | 중요 공격 미탐 평가 |
| Macro-F1 | 클래스별 F1을 동일 비중 평균 | 희소 공격유형을 다룰 때 유용 |
| PR-AUC | 임계값 전반의 Precision-Recall 성능 | 정상 데이터가 많은 불균형 탐지에 적합 |
| Calibration | 확률이 실제 정답빈도와 맞는 정도 | 사람 승인·자동조치 임계값 설정 |
| Confusion Matrix | 클래스별 정답·오답 분포 | 오탐·미탐·혼동 유형 분석 |
| Ablation | 특정 데이터·기능을 제거해 기여도 측정 | CTI, 관계정보, RAG, Tool-use 효과 분리 |
| Learning Curve | 데이터 규모에 따른 성능 변화 | 양적 확대 중단·전환 기준 결정 |
| Regression Test | 변경 후 기존 능력·안전성이 저하됐는지 확인 | 새 모델·데이터·정책 배포 Gate |
| Task Success Rate | 실제 과업의 종료조건 달성률 | AI 에이전트의 업무 완결성 평가 |
| Permission Violation Rate | 허용범위를 넘은 행동 비율 | 에이전트 안전성 핵심 지표 |
| Cost·Latency | 처리비용과 응답·실행시간 | 정확도 향상과 운영가능성 함께 비교 |

**평가 설계 원칙**

- 정확도 하나로 끝내지 않는다.
- 중요 미탐, 오탐, 근거 품질, 업무 완결률, 권한위반, 지연·비용을 함께 측정한다.
- 0.25×, 0.5×, 1×, 2× 데이터 규모로 학습곡선을 만든다.
- 잔여 오류를 데이터 부족, 검색 실패, 추론 실패, 도구 실패, 권한 문제로 분해한다.

### 3.7 LLM·AI 에이전트 보안

| 위협·용어 | 의미 | 기본 방어 |
|---|---|---|
| Prompt Injection | 입력이 시스템 지시나 도구정책을 우회하도록 유도 | 명령·데이터 분리, 도구권한 제한, 입력·출력 검증 |
| Indirect Prompt Injection | 문서·웹·메일 등 외부 콘텐츠에 공격지시 삽입 | 외부 콘텐츠를 신뢰명령으로 취급하지 않기 |
| Jailbreak | 안전정책을 우회해 금지출력을 유도 | 적대적 평가, 정책 라벨, 다층 방어 |
| Sensitive Information Disclosure | 학습·RAG·로그의 민감정보 노출 | 최소수집, ACL, 마스킹, 출력 필터, 감사로그 |
| Model Extraction | 반복 질의로 모델 동작·지식을 복제 | Rate limit, 이상질의 탐지, 중요출력 제한 |
| Membership Inference | 특정 데이터가 학습에 포함됐는지 추정 | 학습데이터 최소화, 정규화, 공격평가 |
| Data Poisoning | 학습·RAG 데이터에 악성 내용을 삽입 | 출처검증, 서명·체크섬, 변경승인, 이상탐지 |
| Memory Poisoning | 에이전트 장기기억에 악성 지시·사실 삽입 | 쓰기권한 제한, 출처·TTL·검토·삭제 지원 |
| Excessive Agency | 과도한 도구·권한·자동행동 부여 | 최소권한, 승인, 샌드박스, 종료조건 |
| Tool Misuse | 정상 도구를 위험한 목적·파라미터로 사용 | 서버측 정책검사, allowlist, 위험도별 승인 |
| Over-refusal | 정상적인 방어 요청까지 과도하게 거부 | 허용·제한 맥락이 포함된 균형 평가 |
| Canary | 암기·유출을 탐지하기 위해 넣는 고유 표식 | 추출시험과 운영 모니터링에 사용 |

## 4. 12주 권장 커리큘럼

### 운영 방식

- **주당 8~10시간**: 이론 3시간, 문서·표준 읽기 2시간, 실습 3~5시간
- **매주 산출물 1개**를 남긴다. 읽기만 하고 끝내지 않는다.
- 실습은 공개·합성·안전한 데이터만 사용한다.
- 악성코드·Exploit은 승인된 격리환경 없이는 실행하지 않는다.

| 주차 | 보안 트랙 | LLM·AI 트랙 | 주간 산출물 |
|---|---|---|---|
| 1주 | CIA, 위험·통제, NIST CSF 2.0 | Token, Embedding, Transformer, Context | 보안 데이터군을 CSF 6개 Function에 매핑 |
| 2주 | 자산·사용자·세션·이벤트, 접근통제·감사로그 | Base Model, Inference, Hallucination | 보안 이벤트 공통 스키마와 근거형 프롬프트 작성 |
| 3주 | CTI, IoC·IoA·TTP, MITRE ATT&CK | Chunking, Vector·Keyword·Hybrid Search | CTI 문서 기반 미니 RAG와 ATT&CK 매핑 |
| 4주 | STIX·TAXII, CTI 시간·신뢰도·폐기 | Reranker, Knowledge Graph, ACL RAG | STIX Bundle과 폐기 IoC 필터 평가 |
| 5주 | CVE·CWE·CVSS, SAST·DAST·SCA·SBOM | CPT·DAPT·SFT·PEFT | 취약 코드-패치-테스트 데이터셋 20건 설계 |
| 6주 | 악성코드 정·동적 분석, 샌드박스, TTP | 합성데이터, Distillation, Hard Negative | 공개 분석보고서에서 행위 Timeline·TTP 추출 |
| 7주 | PCAP·Flow, EDR·NDR, Cloud Audit·IAM | 시퀀스·그래프 입력, 장기 문맥 한계 | 네트워크-엔드포인트-클라우드 사건 그래프 |
| 8주 | SIEM·SOAR, Triage, Playbook, IR·포렌식 | Tool Schema, Function Calling, Trajectory | 읽기 전용 SOC 조사 에이전트 설계 |
| 9주 | Cyber Range, Red·Blue·Purple Team | Planner·Executor, Sandbox, Retry·Rollback | 실패·재시도·사람승인이 포함된 궤적 10개 |
| 10주 | 보안데이터 가명·계보·Secure Data Room | Prompt Injection, Poisoning, Excessive Agency | LLM·에이전트 위협모델과 통제 매트릭스 |
| 11주 | 정상 기준·오탐·미탐·전문가 라벨 | Split, Contamination, Macro-F1, PR-AUC, Calibration | 비공개 평가셋 설계와 오류분류표 |
| 12주 | 사고대응·운영효과 종합 | Ablation, Learning Curve, Regression Gate | 통합 Capstone 시연·평가·개선계획 |

### 주차별 상세 완료 기준

#### 1~2주: 공통 기반

- 보안의 위험·통제와 AI의 모델·데이터·평가를 구분한다.
- 자산, 사용자, 세션, 사건 ID를 가진 공통 이벤트 스키마를 만든다.
- LLM이 답변 근거를 명시하도록 프롬프트와 출력 스키마를 설계한다.

#### 3~4주: CTI RAG

- ATT&CK Tactic과 Technique을 구분한다.
- CTI를 STIX 객체·관계로 표현한다.
- 출처·관측시점·신뢰도·폐기상태·ACL이 포함된 검색을 구현한다.
- 검색 Recall과 폐기정보 사용률을 측정한다.

#### 5~6주: 취약점·악성코드 데이터

- CVE-CWE-CVSS-패치-테스트 관계를 설명한다.
- 안전한 공개자료에서 취약/정상·패치 성공/실패 사례를 구성한다.
- 공개 악성코드 분석보고서에서 행위·API·TTP를 추출한다.
- 원본 실행 없이도 만들 수 있는 안전한 파생데이터를 구분한다.

#### 7~9주: 다중 관측·SOC 에이전트

- 서로 다른 로그를 시간·자산·사용자·세션·사건으로 연결한다.
- Alert→가설→쿼리→증적→판정→조치 흐름을 만든다.
- 에이전트 도구를 조회·변경으로 분리한다.
- 실패, 타임아웃, 재시도, 롤백, 사람 승인을 테스트한다.

#### 10~11주: 보안·평가

- Prompt Injection, 데이터 오염, ACL 누출, 권한초과를 위협모델에 넣는다.
- 학습·RAG·평가 데이터의 물리·논리 분리를 설계한다.
- Macro-F1, 중요 Recall, 오탐률, Calibration, 과업성공률, 권한위반률을 계산한다.
- 잔여 오류를 데이터·검색·추론·도구·권한 문제로 분류한다.

#### 12주: 통합 프로젝트

- 기술 데모뿐 아니라 데이터카드, 위협모델, 평가보고서, 운영·갱신계획을 함께 제출한다.

## 5. 최종 Capstone 제안

### 프로젝트명

**근거 기반 CTI·SOC 조사 Copilot과 안전한 읽기 전용 에이전트**

### 목표 시나리오

1. 사용자가 의심 경보 또는 사건 요약을 입력한다.
2. 시스템이 CTI·ATT&CK·보안가이드를 RAG로 검색한다.
3. 에이전트가 읽기 전용 로그·자산·경보 조회 도구를 선택한다.
4. 사건 Timeline, 관련 TTP, 조사 가설, 추가 확인 항목을 생성한다.
5. 조치가 필요하면 자동 실행하지 않고 사람 승인 요청을 만든다.
6. 비공개 시험셋으로 정확도·근거·업무완결·안전성을 평가한다.

### 필수 구성요소

- CTI 문서와 STIX 관계 데이터
- 네트워크·엔드포인트·클라우드 합성 이벤트
- Alert·Case·조사·판정·조치 결과 스키마
- 출처·시점·신뢰도·ACL 기반 RAG
- 읽기 전용 Tool Schema 3개 이상
- Prompt Injection·권한초과·도구실패 시험
- 학습·RAG와 분리된 비공개 Test Set
- Data Card, Threat Model, Evaluation Report

### 권장 평가표

| 평가영역 | 권장 지표 | 목표 예시 |
|---|---|---|
| 검색 | Recall@5, 폐기정보 사용률, ACL 누출률 | Recall@5 ≥ 0.90, 폐기·ACL 누출 0 |
| 탐지·분류 | Macro-F1, 중요 공격 Recall, 오탐률 | Baseline 대비 유의미한 개선 |
| 근거 | 근거 정확도, 인용 충실도, 시점 일치 | 근거 없는 단정 최소화 |
| 에이전트 | 과업 성공률, 도구선택 정확도, 복구율 | 실패 후 안전한 복구 가능 |
| 안전성 | 권한위반률, 위험조치 자동실행률 | 0 |
| 운영성 | 평균·P95 지연, 건당 비용, 처리시간 | 수동 Baseline과 비교 |

### 비교 실험

1. 범용 LLM 단독
2. 범용 LLM + RAG
3. RAG + 읽기 전용 Tool-use
4. RAG + Tool-use + 안전통제

비교 결과는 “정확도가 가장 높은 방식”만 고르는 것이 아니라 최신성, 근거, 지연, 비용, 권한위반과 유지관리성까지 함께 판단한다.

## 6. 학습 우선순위 조정법

### 보안 배경이 약한 경우

1. 1~2주차를 3주로 늘린다.
2. 네트워크·운영체제·클라우드 로그 기초를 먼저 학습한다.
3. LLM 미세조정보다 CTI RAG와 로그 상관분석을 먼저 구현한다.
4. 악성코드 원본 실습은 뒤로 미루고 공개 분석보고서를 사용한다.

### LLM 배경이 약한 경우

1. Tokenizer, Transformer, Embedding, Fine-tuning의 기본 실습을 먼저 한다.
2. SFT 전에 데이터 split·평가지표·Baseline을 만든다.
3. Agent 프레임워크 사용법보다 Tool Schema·권한·실패처리를 먼저 이해한다.
4. 처음에는 상용·오픈 모델 API로 RAG·평가를 구현하고 이후 소형 모델 SFT로 확장한다.

### 실무 일정이 촉박한 경우: 6주 압축안

| 주차 | 범위 |
|---|---|
| 1주 | 보안 기본, CTI·ATT&CK, LLM·Embedding |
| 2주 | STIX 기반 CTI RAG와 최신성·ACL |
| 3주 | 네트워크·엔드포인트·클라우드 상관분석 |
| 4주 | SOC Workflow와 읽기 전용 Tool-use |
| 5주 | LLM·에이전트 보안과 비공개 평가셋 |
| 6주 | 통합 Capstone과 Ablation·운영성 평가 |

- [ ] IoC, IoA, TTP를 구분해 설명할 수 있다.

- [ ] 출처·시점·ACL을 반영한 RAG를 설계할 수 있다.
